🌌 Synapse — Jira Delivery Intelligence

Gemini AI Analysis SVG Dependency Graph iOS 16 Glassmorphism DOMPurify XSS Filter 3-Panel Command Center

A command center for Jira delivery paths — interactive SVG dependency graphs, sprint delivery metrics, and contextual Gemini AI issue risk analysis, built directly from inside the PM workflow. Designed with a native iOS 16 frosted glass aesthetic and spring-physics interaction models.

1. Workspace Architecture

Synapse integrates delivery execution and risk assessment into a unified three-panel cockpit:

🗂️ Epic Navigator & Sprint Health

  • Epic Summaries: Active Epic hierarchy, key deliverables, and target sprint deadlines.
  • Progress & Velocity: Real-time completion meters and status distribution (Todo / In Progress / Done / Blocked).
  • Fast Filter Chips: Instant one-click filtering by issue state, assignee, or priority without page reloads.

📋 Detailed Issue Inspector

  • Metadata Chips: Sprint assignments, story point estimates, priority badges, and issue types.
  • Tabbed Deep Dive: Markdown description viewer, live comments stream, linked issue relationships, attachments, and audit history timeline.
  • DOMPurify Sanitization: All rendered Markdown and ticket descriptions are strictly sanitized against XSS.

2. Contextual Gemini AI Analysis

Traditional issue trackers record what happened in the past, but fail to predict what will stall delivery in the future. Synapse embeds an AI delivery copilot directly in the Contextual Intelligence sidebar:

✨ Automated Issue Diagnostics & Risk Formulation

  • ⚡ Instant Risk Assessment: Analyzes ticket descriptions, comments, and subtask dependencies to identify hidden technical debt, ambiguous requirements, and scope creep.
  • 🚧 Blocker & Dependency Detection: Uncovers critical path bottlenecks, upstream prerequisites, and stalled cross-team handoffs.
  • ❓ Open Questions & Next Actions: Generates targeted clarifying questions for engineering standups and sprint planning to eliminate delivery ambiguity before coding begins.
  • ⏳ Interactive Skeleton Loading: Smooth UI feedback with animated shimmer states while fetching Gemini AI reasoning via serverless proxy.

3. Dependency Graph Engine

Replaces manual cross-referencing with a dedicated graph canvas that dynamically models relationships:

  • Dynamic Vector Paths: Generates smooth Bezier curves connecting parent Epics, child issues, and blocking dependencies (`blocks`, `is blocked by`, `relates to`).
  • Bottleneck & Critical Path Highlighting: Visually isolates blocked issues and high-risk nodes so delivery leads can identify release blockers at a glance.
  • Interactive Canvas Toolset: Custom pan, zoom, and auto-centering controls built purely in Vanilla JS and SVG without heavy third-party graph dependencies.

4. Design & Motion System

  • 🌌 Pastel Fluid Backdrop: Warp-animating vector mesh blobs float behind frosted glass, shifting colors dynamically to correspond with Light/Dark theme changes.
  • ✨ Frosted Glassmorphism: High-blur surfaces (backdrop-filter: blur(24px) saturate(180%)) with semi-transparent, ultra-thin borders for optimal contrast.
  • 🎛️ Segmented Capsule Controls: Navigation inputs and detail tabs styled as elevated capsule buttons inside rounded sliding tracks matching native iOS settings.
  • 💫 Tactile Spring Easing: Custom cubic curves (cubic-bezier(0.16, 1, 0.3, 1) and cubic-bezier(0.34, 1.56, 0.64, 1)) paired with a tactile press-scale down (transform: scale(0.96)) on click targets.

5. Backend Proxy & Security

  • Google Apps Script Gateway (`Code.gs`): Acts as a secure, serverless CORS proxy between the static client and the Gemini AI API, ensuring zero private API keys or tokens are exposed to the browser.
  • XSS Prevention: All user-supplied descriptions and AI-generated outputs pass through DOMPurify sanitization.
  • Zero Client Secrets: Enterprise credential headers and AI tokens remain fully secured on the backend.

✈️ CrewTask — Air Cargo Warehouse Operations & WDO ERP

PHP 7.4 – 8.3 MySQL / MariaDB 12 Relational Tables Mobile PWA Ready Zero-Framework Vanilla Arch

Enterprise-grade, zero-bloat Air Cargo Warehouse Delivery Order (WDO) & Consignment Tracking Platform. Designed by cargo operations professionals to replace messy spreadsheets, phone tag, and lost freight with real-time visibility, shift accountability, and instant immutable audit trails.

1. Operational Overview

Air cargo floor operations require split-second status handovers across multi-tier shifts, rapid physical cargo location tagging, customs clearance coordination with Customs House Agents (CHAs), and strict chain-of-custody compliance. CrewTask delivers this through an ultra-responsive, lightweight architecture with zero framework overhead.

2. Cargo Lifecycle Workflow

Every shipment advances through a structured, auditable 5-stage lifecycle state machine:

STAGE 1
📥 Intake & Allocation (Allocated): Generates unique Warehouse Delivery Order (WDO) numbers linked to Master Air Waybill (MAWB) and House Air Waybill (HAWB), allocating initial bay/rack location.
STAGE 2
📍 Bay Retrieval (Parcel Located): Floor marshals locate the consignment on warehouse racks, scan tags, and confirm physical presence via the touch PWA.
STAGE 3
🔍 Customs Clearance (Moved to Examination): Consignment moves to customs inspection bay; clearing agent seal numbers and release orders are recorded.
STAGE 4
🚛 Gate Dispatch (Moved to Delivery Gate): Validates IATA Mod-7 AWB check-digit algorithms and issues gate pass for cargo truck loading.
STAGE 5
✅ Final Handover (Delivered): Receiver sign-off, final timestamping, and automatic archival with immutable audit logging.

4. Relational Database Schema (12 Tables)

The relational architecture uses indexed foreign constraints and InnoDB storage engine:

  • tickets — Core cargo manifest storing WDO, MAWB, HAWB, package counts, locations, and lifecycle statuses.
  • ticket_status_log — Timestamped audit of every status transition across shifts.
  • staff_assignment — Staff allocation and shift duty assignment history per consignment.
  • ticket_audit_log — Comprehensive change history capturing old vs. new values, operator IDs, and timestamps.
  • users — User profiles, Bcrypt credentials, approval statuses, and session versions.
  • password_resets — Expiring, single-use security tokens for password resets.
  • site_settings — Key-value system configuration store (e.g., default theme).
  • cha_list — Directory of active Customs House Agents.
  • locations — Warehouse storage bays, cold rooms, and rack zones.
  • admin_activity_log — Administrative audit trail for role changes, approvals, and system adjustments.
  • login_attempt_log — Security log tracking failed and successful authentication events by IP.
  • shift_notes — Digital logbook for handover notes between shifts.

5. Security & Session Hardening

  • SQL Injection Prevention: 100% of dynamic queries use parameterized prepared statements ($stmt->prepare() / $stmt->bind_param()).
  • Cross-Site Request Forgery (CSRF): All mutating POST and AJAX requests require a valid session CSRF token verified via includes/csrf.php.
  • Cross-Site Scripting (XSS): Output rendering is sanitised through htmlspecialchars() with strict UTF-8 encoding.
  • Session Protection: Session cookies use HttpOnly, SameSite=Lax, and Secure flags when HTTPS is active.
  • Instant Revocation: Incrementing session_version in the database immediately invalidates compromised or stale user sessions without restarting the server.

✈️ AWB Mod-7 Tool — Technical Specification

Manifest V3 100% Offline Client-Side IATA Standard Check-Digit Cross-Browser (Chrome / Firefox) Zero Permissions Required

A zero-dependency, privacy-first browser extension and offline engine to generate and verify Air Waybill (AWB) numbers using IATA's international Mod-7 standard — the same check-digit logic airline ERPs (CargoWise, iCargo, Cargospot, SAP TM) depend on.

1. IATA Mod-7 Algorithm

An Air Waybill tracking number consists of a 3-digit airline prefix followed by an 8-digit serial number where the 8th digit is an algebraic check digit:

Structure: [3-Digit Prefix] - [7-Digit Base Serial][1-Digit Check Digit]

Formula: Check Digit = (7-Digit Base Serial) mod 7

Example: Base Serial = 1234567
Calculation: 1234567 % 7 = 5
Full Valid AWB: 176-12345675

2. Industry Rationale: Mod-7 vs. Mod-10 (Luhn)

While banking and credit cards standardized on the Luhn (Mod-10) algorithm to catch character transpositions, the global airline industry adopted Mod-7 in early telex messaging standards because:

  • Single-Step Compute: Simple modulo 7 arithmetic required minimal hardware memory in early legacy mainframes.
  • Global Switching Invariance: Billions of historical physical paper manifests, customs clearing archives, and multi-carrier interline EDI pipelines are anchored on Mod-7, making industry-wide migration costs prohibitive.

3. Extension Architecture (Manifest V3)

  • Zero Permission Footprint: Uses permissions: [] with zero web access, zero network calls, and zero external tracking.
  • Cross-Browser Manifest: Packaged for Google Chrome, Brave, Microsoft Edge, Opera, and Mozilla Firefox from one core codebase.
  • Native Clipboard API: Instant 1-click clipboard write for QA automation and manual terminal data entry.

📋 CensusConnect — Field Demographic Registry Specification

Progressive Web App (PWA) Offline Service Worker Bilingual i18n (EN/HI) Google Apps Script REST Local Storage Cache

A resilient, mobile-first Progressive Web App designed for field enumerators capturing multi-tier household mapping, socio-economic classifications, and living amenity access offline in English or Hindi.

1. Survey Questionnaire Modules

Every surveyed household unit is mapped hierarchically through 4 distinct modules:

📍 Section 1: Household Mapping & Structure

Classifies building structures (Pucca, Semi-Pucca, Kutcha, Independent House, Apartment) and legal tenancy / ownership status.

👤 Section 2: Demographic Profile

Captures Head of Household full legal identity, validated 10-digit mobile contact, total family size, and community grouping.

💼 Section 3: Socio-Economic & Livelihood Registry

Tracks primary livelihood sources (Salaried, Self-Employed, Farming, Daily Wage), unique Socio-Economic IDs (SE-ID), and welfare scheme enrollments (Ration, Ayushman Health, PMAY Housing).

🏠 Section 4: Household Amenities & Field Notes

Audits drinking water sources (treated piped, borewell, tanker), sanitation / cooking fuel facilities, and qualitative field officer observations.

2. Offline Storage & Backend Sync

CensusConnect ensures field survey continuity even in zero-connectivity environments:

  • Service Worker Caching (sw.js): Stores application shells and assets locally for immediate offline loading.
  • Client-Side Storage: In-flight survey submissions and record modifications persist locally without data loss during connectivity drops.
  • Serverless Cloud Sync: Pushes validated, structured JSON payloads directly to a centralized Google Sheets / Apps Script database endpoint upon restoration of connectivity.

3. Bilingual Internationalization (i18n)

Features dynamic 1-click UI translation between English and हिन्दी (Hindi). All form inputs, validation error toasts, dropdowns, and field instructions switch instantly without page reload.

⚡ Fitness OS — Technical Specification & Math Engine

Next.js & TypeScript 100% Client-Side LocalStorage Mifflin-St Jeor Formula 7-Day Rolling Trend Multi-Profile PIN Lock

A phone-first, fully private fitness and nutrition engine — precision calorie budgeting, OpenGym workout logging, 7-day rolling weight analytics, and an offline-resilient AI coach, with zero data ever leaving the device.

1. Metabolic & Nutrition Formulas

1. Basal Metabolic Rate (BMR — Mifflin-St Jeor):
BMR(Male) = 10 × Weight(kg) + 6.25 × Height(cm) - 5 × Age + 5
BMR(Female) = 10 × Weight(kg) + 6.25 × Height(cm) - 5 × Age - 161
2. Total Daily Energy Expenditure (TDEE):
TDEE = BMR × Activity Multiplier (1.2× Sedentary to 1.9× Heavy Athletic)
3. Fat Loss Energy Deficit:
1 kg Body Fat ≈ 7,700 kcal energy equivalent
Daily Deficit = (7,700 × Planned kg Loss) / Total Days Target
4. Muscle Preservation Protocol:
Protein Target = 2.2 g per kg of body weight to retain lean tissue during caloric deficit.

2. AI Coaching Engine & Offline Fallback

Engine Trigger Condition Behavior & Architecture
🤖 Live OpenAI Engine User provides custom API Key Direct client-side streaming from `gpt-4o-mini` generating contextual adjustments based on 7-day rolling average trends.
🛡️ Offline Rule-Based Fallback No API Key or Offline Device Deterministic heuristic engine analyzing delta vs target pace across 5 dimensions: Nutrition, Training, Hydration, Recovery, Mindset.

3. Client-Side Privacy Architecture

  • Partitioned LocalStorage: Multi-profile isolation (e.g. Personal, Partner, Guest) stored 100% locally.
  • PIN Privacy Lock: Optional 4-digit PIN encryption for client-side profile security.
  • Zero Data Exfiltration: No database servers, no tracking analytics, and zero cloud hosting cost.
